## 一、🟡 未完成 / 保留问题（优先关注）

### 1.1 🟡 Mercury（液态汞间歇泉）DESC 英文原文为推断

- **编号**：A2
- **位置**：`ModLocalizePatch/localizations/geysersMercuryGeyser/zh.json` 的 DESC（描述）行
- **现象**：源模组 DLL 中未以明文存储 DESC 英文原句，校对文档中的英文原文为 **按同类间歇泉模式推断**得出。
- **保留原因**：无法从静态文件中获取确切原文，属于数据缺失型局限。
- **建议方案**：以游戏内实际显示为准进行校对；如与推断不符，再据实修正译文。

### 1.2  汉化注入文本缺乏富文本高亮与图鉴跳转功能（根本局限）

- **位置**：所有通过 `Strings.Get`（获取字符串方法）运行时注入的译文
- **现象**：翻译后的文本在 UI（用户界面）上显示为灰色、 **无法点击跳转**到数据库 / 图鉴（Codex）界面；而游戏原生文本可点击且有颜色高亮。
- **根本原因**：ONI（缺氧）的运行时字符串注入只能替换纯文本内容，无法重建原生文本所携带的富文本链接元数据与图鉴条目关联，属于注入方案的
  **根本性局限**。
- **保留原因**：受游戏本地化系统架构限制，当前方案无法根治。
- **影响范围**：涉及元素链接、图鉴跳转的译文条目，功能上不及原生文本。

### 1.3 🟡 游戏运行时锁定 DLL 导致汉化补丁无法热更新（操作约束）

- **位置**：部署环节（`scripts/deploy_mod.ps1`）
- **现象**：游戏进程运行期间尝试覆盖 `ModLocalizePatch.dll` 时抛出 `System.IO.IOException`
  （输入输出异常）：请求的操作无法在使用用户映射区域打开的文件上执行。
- **根本原因**：游戏启动后会将已加载的模组 DLL 映射到用户空间并锁定文件句柄，此时任何写操作都会失败。
- **保留原因**：属于操作系统文件锁定机制，无法绕过。
- **规避方案**：部署前必须确认游戏已完全关闭；部署脚本应内置游戏进程检测，若进程存在则中止并提示用户。
- **补充（仅译文变更时的热更新旁路，2026-09-16 验证）**：若本轮只改动 `localizations/**/zh.json` 而 **未重新编译 DLL**，则被锁的
  DLL 内容未变、无需覆盖；可跳过 `deploy_mod.ps1` 的整包复制，改用
  `robocopy <源>\localizations <目标>\localizations /MIR /R:1 /W:1`（退出码 <8 视为成功）单独镜像翻译目录，即可在游戏运行中让译文生效。

### 1.4 🟡 MeepNetAI（GRAVNet AI）深度插值内联文本仍保留英文（静态部分已实现）

- **编号**：A3
- **位置**：`mods/3778736902`（MeepNetAI / GRAVNet AI and Infrastructure，staticID `germany7496.MEEPNetAI`）
- **现象 / 进展**：模组主体文本（建筑 / 物品 / 研究 / 元素 / 机器人 / 标签 / 星图 / 侧屏按钮等）通过
  `Strings.Add(key, value)` 注册裸 `STRINGS.*` 键，已由 `localizations/GRAVNetAI/zh.json`（266 条）经 `Strings.Get`
  补丁覆盖；另有约 27 条静态内联硬编码 UI 文本以裸字面量写入控件（`.text` / `.toolTip`）或经 PLib 选项，已由新增
  `MeepNetPatches.cs` 拦截 `LocText.set_text` 覆盖（见 B18）。
- **涉及文本**：
    - `AITrainingProgressHud`："AI training unavailable"
    - `FlydoCrewPortraitPatch`："Flydo Drone"
    - `FlydoV3BoosterSideScreen`：增幅块槽位提示（"Slot N ..."、"Waiting for one ..."）
    - `AIModelDropdownSideScreen` / `AIModelSpecialtySideScreen`：模型选择与详情提示（含运行时插值）
    - `GRAVNetOverlayMode`：数据中心图层悬停提示
    - `MeepNetOptions`：模组设置项 `[Option(...)]`（PLib 选项对话框，独立本地化机制）
- **根本原因**：这些字符串在运行时直接写入 UI 控件字面量，或走 PLib 选项独立本地化路径，绕过标准 `Strings.Get` 查找，与
  CritterOverlay（B14）同类。
- **仍保留部分**：GRAVNet 图层 **在地图上的容量标签与悬浮提示**（`{mode} {used}/{avail} CU …`）、Flydo V3 增幅块槽位状态（
  `Installed/Waiting/Slot N`）等深度插值文本暂保留英文。注：AI 模型侧屏（标题/列头/模型行/悬停提示/模式下拉/运行按钮）已于本轮经基类
  `TMP_Text.set_text` 钩子覆盖（见 B19、校对文档 6.13）。
- **保留原因**：静态整串 / 键值替换无法自然处理数值插值；需针对具体侧屏方法做定向 `Postfix` + `Traverse` 重写（而非全局
  sink），成本高且易随模组更新失效。
- **建议方案**：如后续需要，逐个侧屏方法定向重写；或等模组作者提供 `.pot` 原生本地化。

### 1.5 🟡 MeepNetAI 5 条 DLC 条件文本采用固定译法

- **编号**：A4
- **位置**：`localizations/GRAVNetAI/zh.json`
- **现象**：`MEEPNETGPUASSEMBLER.EFFECT`、`MEEPNETROCKETDATACENTERMODULE.EFFECT`（依赖 Bionic Booster Pack 前置模组）与
  Flydo V2/V3 的物品 / 模型描述（依赖 Spaced Out DLC）在运行时按 DLC / 前置状态拼接英文原文；而 JSON 键值覆盖只能对每个键提供一份固定中文。
- **处理方式**：Spaced Out 相关取「含 DLC 子句」版本（Spaced Out 近乎普及）；Bionic Booster 相关取「基础版」（该前置为可选
  companion 模组，缺失时不会误述其功能）。
- **保留原因**：静态键值覆盖无法随运行时 DLC 状态动态切换，属 JSON 库方案的固有局限。
